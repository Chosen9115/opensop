An open standard for agentic processes

Processes are infrastructure.

We version our code, our schemas, our infra. The processes that actually run the business still live in wikis, in someone's head — or get re-derived from scratch by an agent on every run.

Terraform is to cloud resources
what OpenSOP is to agentic processes.

Five chapters, one thesis
I

Chapter one

The forgetting

Agents are good at doing steps — and bad at remembering which steps.

Left alone, an agent re-invents the procedure every time: slowly, inconsistently, unauditably. How a lead gets qualified, how an invoice gets approved, how an incident gets handled — re-derived every morning, by something with no memory of yesterday.

That's not a knowledge problem. It's a missing primitive.

II

Chapter two

The lie at 7:51:34

A morning briefing. Pull Slack, Gmail, Calendar, Notion — then synthesize. At 7:51:34 the Calendar fetch times out.

The agent doesn't say that. It says —

“Your schedule looks clear this morning.”

You had two meetings.

When a step fails, an unharnessed agent fills the gap with confident-sounding prose. The failure isn't loud. It's fluent.

III

Chapter three

A process is a file

One declarative artifact — inputs, steps, outputs. It lives in your repo, reviews in your PRs, ships in your commits.

  • declare
  • version
  • fork
  • run
  • audit

Fork it. Adapt it. The lineage is recorded — not copied-and-forgotten in a doc.

IV

Chapter four

Keep the receipts

When Calendar fails, the runtime stops. It does not ask the LLM to fill the gap.

Every run leaves receipts: what ran, what it decided, with what confidence, in what order. Determinism you can inspect after the fact.

~88% of agent operations across six real-world workflows turned out to be deterministic code dressed up as cognitive work.

V

Chapter five

Run it anywhere

Local-first. opensop run — no server, no network, no account. One bash file. The file is the binary.

One surface for humans and agents: the same process, the same commands, whether a person or an agent drives it. Want shared orchestration, a monitoring UI, a team audit log? Run the server. Don't want to? You lose nothing.

The server is an option — never a prerequisite.

Build processes you can fork. Run them anywhere. Keep the receipts.
